  pip install ultralytics opencv-python

  ▎ 如果树莓派用的是 libcamera（较新的 Raspberry Pi OS），OpenCV 
  ▎ 读取摄像头时可能需要额外配置，但纯图片推理不受影响。

  第三步：单张图片测试

  在树莓派项目目录下执行：

  python test_yolo.py predict <你的图片路径.jpg>

  或者写一个简单的 Python 测试脚本（更灵活）：

  from ultralytics import YOLO

  # 加载模型
  model = YOLO('models/plant_organ_detection_h100x2_best.pt')

  # 推理单张图片
  results = model('你的植物图片.jpg', imgsz=640)

  for result in results:
      for box in result.boxes:
          class_id = int(box.cls[0])
          class_name = model.names[class_id]
          confidence = float(box.conf[0])
          print(f"检测到：{class_name}，置信度：{confidence:.2%}")

      # 保存结果图
      result.save(filename='output.jpg')

  第四步（可选）：接摄像头实时测试

  如果树莓派接了 USB 摄像头，可以用下面这个脚本做实时检测。建议先把 imgsz 降到 
  320 或 416，否则会很卡：

  import cv2
  from ultralytics import YOLO

  model = YOLO('models/plant_organ_detection_h100x2_best.pt')
  cap = cv2.VideoCapture(0)  # USB 摄像头

  while True:
      ret, frame = cap.read()
      if not ret:
          break

      # imgsz=320 在树莓派上会快很多
      results = model(frame, imgsz=320, verbose=False)
      annotated = results[0].plot()

      cv2.imshow('Plant Detection', annotated)
      if cv2.waitKey(1) & 0xFF == ord('q'):
          break

  cap.release()
  cv2.destroyAllWindows()

  为什么先测现有模型？

  1. 验证链路是否通 — 模型文件、依赖环境、推理脚本是否都能正常工作？如果连
  yolov8l 在 PC
  上都跑不出结果，说明环境或代码有问题，直接拿去树莓派只会更难排查。
  2. 确认效果是否满足需求 — 指标看起来不错（mAP@50 有 0.912），但实际拿你的照片
  测一下，看看对具体植物的检测效果是否满意。如果模型本身对目标植物表现不好，换
  yolov8n 重新训练也救不回来，可能需要调整数据集。
  3. 避免无效工作 — 如果现有模型已经能很好工作，你的目标就只是“让它在树莓派上跑
  得快”，那下一步的方向就很明确：蒸馏/导出轻量模型。如果模型效果不好，那问题在数
  据或训练，而不是模型大小。

  结果分析

  1. 模型泛化性一般

  这个模型训练用的数据集是
  Nature3（野外/自然场景的植物叶片、花朵、果实），而你测试的是室内盆栽植物照片。
  第一张图完全没有检测到任何目标，说明模型对这种室内场景、这种叶片形态的泛化能力
  不够强。第二张图检测到了一片叶子，但也没有框出全部叶片。

  2. 推理速度很慢

  在 PC 的 CPU 上跑一张图就要 ~1 秒。如果搬到树莓派上，同一张图可能需要 3~8 
  秒，几乎无法做实时视频流检测。

  3. 下一步建议

  结论：直接把这个 yolov8l 模型部署到树莓派上，效果不会理想。

  更合适的方案有两个：

  方案: A. 收集自己的数据集重新训练
  做法: 拍几十到几百张你的目标植物的叶子/花/果实照片，用 YOLOv8n
    训练一个专属轻量模型
  优缺点: ✅ 最准、树莓派能跑得动❌ 需要花时间拍照和标注
  ────────────────────────────────────────
  方案: B. 先用 yolov8n 在 Nature3 上复训
  做法: 用同样的数据集，但换成 yolov8n.pt 训练一个小模型
  优缺点: ✅ 速度快很多，可能还能检出一些东西❌ 对室内盆栽的泛化问题可能还在

  如果你只是想快速在树莓派上跑起来看看效果，方案 B
  是最快的；但如果你目标是准确识别你实际要检测的植物，方案 A 才是根本解决之道。

  你倾向于哪种方案？或者你想先试试用 yolov8n 快速复训一个轻量版？

● 方案 A 数据集要求

  针对室内 + 树莓派摄像头场景，数据集质量比数量更重要。以下是具体要求：

  ---
  1. 图像数量

  类别: 每类（Leaf/flower/fruit）
  最少数量: 50~80 张
  建议数量: 150~300 张
  说明: 如果你的植物种类固定，每类 150 张左右就能有不错效果
  ────────────────────────────────────────
  类别: 总图像数
  最少数量: 150 张
  建议数量: 500 张左右
  说明: 3 类共 500 张是树莓派轻量模型的甜点区间

  注意：不要只拍同一个盆栽。多拍几种类似的室内植物，模型泛化性会更好。

  ---
  2. 场景多样性（关键！）

  你的测试已经证明：室内盆栽 ≠ 野外自然场景。所以拍照时要注意覆盖以下变量：

  - 光照条件：白天自然光、晚上开灯、背光、侧光、阴影
  - 拍摄角度：正面、侧面、俯视、仰视
  - 距离/缩放：叶子占画面大部分、整株植物、远景
  - 背景变化：白墙、木地板、窗帘、家具、杂乱的桌面
  - 叶片状态：完整的叶子、有虫洞的、枯萎边缘的、重叠的叶子
  - 多目标同屏：一张图里同时有叶子 + 花 + 果实（如果有的话）

  ▎ 💡 核心原则：训练集里的多样性 ≈ 实际运行时的多样性

  datasets/custom_indoor_plant/

  │   │   ├── img_001.jpg

  每个 *.txt 标签文件格式：

  例如：

  6. 训练配置建议（树莓派专用）

  from ultralytics import YOLO

  model = YOLO('yolov8n.pt')  # 一定要用 nano 版，树莓派才能跑流畅

  model.train(
      data='data.yaml',      # 指向你的自定义数据集配置
      epochs=100,            # 100 轮足够
      imgsz=416,             # 416 比 640 快很多，精度损失可控
      batch=16,              # 根据 PC 显存调整
      device=0,              # 用 GPU 训练
      patience=30,           # 30 轮不提升就早停
      name='indoor_plant_pi'
  )

  树莓派部署时的推理参数：
  model = YOLO('runs/detect/indoor_plant_pi/weights/best.pt')

  如果这种误检在实际使用中会困扰你，有几种低成本优化方式：

  1. 提高置信度阈值
  在树莓派推理时用 conf=0.5 或更高：

  1. 这样可以过滤掉那个 49.83% 的杂框，但 74% 的误检可能还在。
  2. 后处理过滤小框
  添加一个面积过滤：如果检测框相对于画面太小（比如占比 <
  1%），就丢弃。那幅墙上的画非常小，容易被过滤。

  补充一些带有"植物海报/装饰画"的室内场景负样本，重新标注训练，让模型学会区分"真
  实的盆栽"和"画里的植物"。

  两个脚本都保留了自动保存逻辑：
  - PyTorch 版：检测到盆栽时每隔 30 帧自动保存
  - NCNN 版：检测到盆栽（且框数正常）时每隔 30 帧自动保存

  ---
  YOLO 能直接提供什么

  YOLO 输出的是图像坐标：
  bbox = [x1, y1, x2, y2]  # 像素坐标，比如 [306, 161, 904, 1473]
  confidence = 0.8232

  从这两个数，你可以推导出：

  信息: 盆栽在画面中的水平位置
  计算方式: center_x = (x1 + x2) / 2
  用途: 判断盆栽在小车左边还是右边
  ────────────────────────────────────────
  信息: 盆栽在画面中的大小
  计算方式: area = (x2-x1) * (y2-y1)
  用途: 越大表示距离越近
  ────────────────────────────────────────
  信息: 盆栽是否在画面中央
  计算方式: center_x vs 画面宽度的一半
  用途: 小车是否正对盆栽

  ---
  小车导航的最简方案

  不需要复杂的深度相机或
  SLAM。对于"小车开过去浇水"这个场景，一个行为式（reactive）控制策略就够了：

  from ultralytics import YOLO
  import cv2

  model = YOLO('best.pt')  # 或树莓派上的路径

  cap = cv2.VideoCapture(0)

  # 小车控制函数（你需要根据实际硬件实现）
  def motor_control(left_speed, right_speed):
      """控制左右轮速度，范围 -100 ~ 100"""
      pass

  while True:
      ret, frame = cap.read()
      if not ret:
          break

      results = model(frame, imgsz=320, conf=0.25, verbose=False)
      boxes = results[0].boxes

      h, w = frame.shape[:2]
      frame_center_x = w / 2

      if len(boxes) == 0:
          # 没检测到盆栽：原地旋转扫描
          motor_control(-30, 30)  # 原地左转
          continue

      # 取置信度最高的盆栽
      best_box = max(boxes, key=lambda b: float(b.conf[0]))
      x1, y1, x2, y2 = best_box.xyxy[0].tolist()
      cx = (x1 + x2) / 2
      box_width = x2 - x1

      # 水平偏差（-1 ~ +1，负表示盆栽在左边）
      horizontal_error = (cx - frame_center_x) / (w / 2)

      # 距离估计（框的宽度占画面宽度的比例）
      # 假设框宽 > 画面宽的 60% 时已经足够近
      proximity = box_width / w

      if proximity > 0.6:
          # 已经足够近，停止
          motor_control(0, 0)
          print("到达盆栽附近，开始浇水！")
          # 触发浇水动作...
      elif abs(horizontal_error) < 0.15:
          # 大致正对，直行
          motor_control(50, 50)
      elif horizontal_error < 0:
          # 盆栽在左边，左转
          motor_control(-20, 50)
      else:
          # 盆栽在右边，右转
          motor_control(50, -20)
